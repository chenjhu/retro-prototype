# Retro

个人每日/每周进度复盘平台（手机端优先）。数据全部是你电脑上的 Markdown 文件，任何 AI 都能直接读写。

- **零依赖**：只需要 Node.js 20+，不用 `npm install`。
- **数据本地化**：每周一个文件 `data/2026-W45.md`，格式见 [docs/DATA_FORMAT.md](docs/DATA_FORMAT.md)。
- **实时同步**：AI 改了文件，打开的网页自动刷新；手机和电脑同时编辑也不会互相覆盖。

## 运行

```bash
npm start
```

终端会打印两个地址：

- `http://localhost:4173`：在这台电脑上打开。
- `http://192.168.x.x:4173`：手机连**同一个 Wi-Fi** 时用这个。

在 iPhone Safari 打开后，点「分享 → 添加到主屏幕」，就会像一个全屏 App 一样运行。

可选环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `4173` | 端口 |
| `DATA_DIR` | `./data` | 数据目录 |
| `HOST` | `0.0.0.0` | 设成 `127.0.0.1` 则只允许本机访问 |

在外面用手机访问：服务没有登录功能，**不要把端口暴露到公网**。推荐装 [Tailscale](https://tailscale.com)（免费），电脑和手机登录同一个账号后，手机用电脑的 Tailscale 地址访问。

## 使用

界面有三种模式，点哪个部分就展开哪个，其余部分收起变灰：

| 点击 | 模式 |
|---|---|
| **Pinned for this week** | 本周置顶任务展开：点最后一个空方框，或左下角 ● + 新增 |
| **某一天的日期** | 这一天放大，日期下方的 ⊕ 新增（打开时默认是今天） |
| **Summary** | 本周总结展开，左下角 ● + 新增 |

- **切换分类**：在日期列表上左右滑动，或者点上方的 `Academic` / `Personal` / `‹ ›`。
- **切换周**：点 `W45 2026` 展开滚轮，上下滑动或点某一行来选周和年份；不在本周时左边会出现 ⊕ 样式的 → 箭头，点它回到本周；再点标题或点别处收起。也可以在顶部那一行左右滑动。
- **编辑**：点文字直接改；按回车在下面新增一条；空的一条按删除键（或直接离开）就会删掉。
- **高亮**：长按任务前面的方框，文字底下会划出一道黄色荧光笔；再长按一次取消。单击方框仍然是打勾。
- 右上角 `3 x ✓` 是本周已完成的任务数（含置顶任务，不含总结）。
- 过去的日期自动变灰，没完成的任务保持黑色；点开过去的某天，它会恢复成黑色方便编辑。
- 第二天打开时自动跳到当天；周一早上自动切到新的一周。
- **自动更新**：主屏幕上的 App 回到前台时，如果服务端代码有更新，会先保存再自动刷新；后台期间别处改过的数据也会同步过来。

## 记录约定

| 写法 | 含义 |
|---|---|
| `- [ ] 名字 · 机构` | 已联系（找到人、准备写信、已发送、已加 LinkedIn），还没回复 |
| `- [x] 名字 · 机构` | 对方回复了 / 关系建立了 |
| `==文字==` | 高亮（重要） |
| `(L)` | 在 LinkedIn 上沟通 |
| `(LC)` | 只在 LinkedIn 发了 connection 请求 |

完整说明在 [docs/DATA_FORMAT.md](docs/DATA_FORMAT.md)。平台每次启动时会把它复制到数据文件夹里，存成 `README.md`，所以只拿到数据文件夹的 AI 也能看懂这些约定。新增缩写的话告诉 Claude，加到这份说明里即可。

## 批量导入

把要加的内容按平台格式写进一个 `.md` 文件（只写需要的部分即可，例如某一天的 `### Work`），在平台运行时执行：

```bash
node ~/Projects/retro-prototype/scripts/merge.js 文件路径.md
```

它只会**追加**新任务；已经存在的同名任务会跳过，所以同一个文件导入两次也不会重复。手机上打开的页面会自动刷新。

## 数据安全

代码怎么迭代，数据都不会丢：

1. **数据和代码分开**：数据在 `DATA_DIR` 里，不在 git 里，`git pull` 更新代码不会碰到它。
2. **格式是固定约定**（[docs/DATA_FORMAT.md](docs/DATA_FORMAT.md)），只做向后兼容的改动。改名时旧名字会自动识别，例如旧文件里的 `### Academics` 会读成 `Academic`。
3. **兼容性测试**：`test/fixtures/` 里存着旧版本格式的文件，`npm test` 会确认它们每一条任务都还能完整读出来。以后每次改格式，都会加一个新的样本文件。
4. **自动备份**：每个周文件每天第一次被修改前，会把原样复制到 `DATA_DIR/.backups/日期/`，保留最近 30 天。
5. 数据放在 OneDrive 里，还会有 OneDrive 自带的版本历史。

## 目录结构

| 路径 | 内容 |
|---|---|
| `server/` | 本地服务：读写 Markdown、JSON API、文件监听、静态页面 |
| `shared/` | 周日期计算、数据模型、Markdown 解析与生成（服务端和浏览器共用） |
| `public/` | 网页：`index.html`，`css/`，`js/`（`store.js` 数据与同步，`app.js` 交互，`items.js` 列表渲染，`gestures.js` 滑动），`icons/` |
| `data/` | 你的数据（运行时自动创建；不进 git）。里面的 `README.md` 是自动生成的格式说明 |
| `docs/` | 数据格式说明，`design/` 设计稿 |
| `test/` | 自动测试：`npm test` |
